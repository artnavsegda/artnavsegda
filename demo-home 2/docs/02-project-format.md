# 02. Формат проекта объекта, редактор, устройства и сцены

> Подробности ответов из ранней части обсуждения сохранились только в сжатом виде. Ниже — решения
> в той форме, в какой они легли в остальную архитектуру: бэкенд, логику, сервисную панель.
> Пункты с пометкой **[сверить]** стоит перепроверить с автором.

## Что такое «проект объекта»

Проект объекта — это **данные, а не программа**. Это декларативная модель дома: этажи, комнаты,
устройства и их адреса, кнопки и привязки, группы, сцены, зоны охраны, медиа-граф, климатические
зоны. К ней добавляются:
- **экземпляры поведений** из библиотеки — типизированные машины состояний с параметрами;
- **модули кода** под конкретный объект — только там, где библиотеки не хватает
  (`04-logic-model.md`).

Как это хранится:
- Формат — JSON или YAML по схеме. Схема описана один раз в TypeBox, по ней же валидация в ядре
  и типы в клиенте.
- Проект — git-репозиторий объекта (isomorphic-git на контроллере). Каждая правка из сервисной
  панели — коммит с автором и причиной. Отсюда «история конфигурации» и откат.
- Клиентский `HouseDef` в прототипе — упрощённая проекция этой модели для интерфейса.

## Конструктор или редактор

- Большой визуальный конструктор в начале **не нужен**. Нужен редактор модели в сервисной панели:
  формы и таблицы по схеме, редактор плана и точек на фото, плюс **горячая перезагрузка**. Ядро
  применяет разницу конфигураций без перезапуска, клиенты получают новый snapshot.
- Программист работает с тем же проектом как с кодом, в git, с проверкой схемы и сухим прогоном
  поведений в симуляторе.
- Интерфейс собирается из модели: меню, группы, зоны медиа, климатические комнаты выводятся из
  конфигурации (`src/client/nav.svelte.ts`). Отдельно рисуются только дизайнерские вещи:
  фото, хотспоты, тренд.

## Новые устройства

Ситуации вроде «добавили лампочку», «поменяли телевизор», «подключили другую консоль» решает
**техник из сервисной панели, без программиста**:
1. Выбирает тип устройства из библиотеки профилей драйверов: KNX-группа, канал Wiren Board,
   ИК-профиль телевизора, Modbus-адрес.
2. Указывает адрес или канал и комнату.
3. Ставит точку на плане и, если нужно, на фото.
4. Для медиа — порт матрицы или вход телевизора, ИК-коды и калибровка таймингов
   (`05-media.md`, экраны AVMap / AVIR / AVCalib).
5. Прогоняет проверочные сценарии и сохраняет. Это коммит в проект, горячая перезагрузка.

Замена вышедшего из строя устройства — отдельный мастер «Замена» в сервисной панели: новый адрес,
перенос привязок и калибровок.

## Сцены и редактор сцен

**[сверить]** Решение в общих чертах:
- **Сцены дома и комнат** — часть проекта. Их настраивает интегратор или техник по данным:
  какие устройства, какие значения, плюс постановка на охрану.
- **Жильцу полноценный редактор сцен не нужен.** Достаточно пары своих сцен в комнате
  («Моя», «Своя») с кнопкой «сохранить текущее состояние сюда».
- Расписания и простые условия на уровне «в 7:00 сцена Утро» можно дать жильцу позже.
  Сложная логика остаётся в поведениях.

В прототипе тоже два вида сцен: сцены дома (`house.scenes`) и сцены комнаты (`house.roomScenes`).
Для комнат без своих сцен показываются стандартные «Ярко / Мягко / Выкл.».
